## 1. 排查方法论：从截图反查到代码

这一节是整篇最值钱的部分。以后任何「这个控件不对劲」都可以照这个顺序走。

### 1.1 第一步：从界面文字反查控件名

WinForms 的界面是 `InitializeComponent()` 里一行行 `new` 出来的，**界面上每一个字都能在 `*.Designer.cs` 里搜到**。

比如截图里卡片上的「通道」：

```bash
grep -rn 'Text = "通道"' View/
```

结果落在 `View/simpleView.Designer.cs:55`：

```csharp
uiTextBox1.Text = "通道";
```

于是知道：这个字属于 `simpleView` 里的 `uiTextBox1`，不是 `mainView` 的控件。
同理搜 `"隐藏通道"` 会命中 `mainView.Designer.cs` 的 `uiButton2`。

> **注意命名空间**：`View/*` 页面与 `Form1` 仍是 `WinFormsApp3.*`，而 `Helper` / `Model` / `Common` 已迁到 `TICP.*`。改 `using` 时两边要对齐，否则报 `CS0234`。

### 1.2 第二步：判断「没绑定」还是「绑定了但报错」

按钮点了没反应，只有两种可能：

1. **没绑定事件** → 点下去什么代码都不会执行；
2. **绑定了但方法里抛异常 / 提前 return** → 通常会弹错误框或写进 `Logs`。

最快的区分方法是搜事件绑定：

```bash
grep -rn '\.Click +=' View/*.Designer.cs
```

输出里能看到 `uiButton1.Click += uiButton1_Click;`、`uiButton3.Click += uiButton3_Click;`，
**唯独没有 `uiButton2`** —— 结论立刻确定：按钮压根没接线。

> 调试习惯：不要一上来猜「是不是 Visible 没生效」。先确认事件有没有被调用
> （在方法第一行打断点，或 `Log.Info("uiButton2_Click")`），这一步能省掉半小时。

### 1.3 第三步：字体类问题要「离屏渲染」验证

界面截图只能看到「有方框」，但看不到是哪个环节丢了字形。可靠做法是**不启动窗体，直接用同一个库画一张 PNG**：

```csharp
var plot = new ScottPlot.Plot();
plot.Font.Set("Microsoft YaHei UI");
plot.Title("通道1 趋势（3 个点）");
// ... 用 SkiaSharp 的 SKCanvas 调 plot.Render(canvas, 900, 450) 存成 PNG
```

这张验证图本次实测结果是：标题、`检测时间`、`测量值`、`通道1` 全部正常，方框消失。
好处是**不需要串口、不需要打开窗体、可重复**，比反复启动上位机快得多。

## 2. Bug 1：让每张卡片显示「通道几」

### 2.1 根因

`mainView_Load` 里循环 8 次 `new simpleView()`。设计器代码是**类级别**的，每个实例都跑同一份 `InitializeComponent()`，
所以 8 张卡片的 `uiTextBox1.Text` 都是写死的 `"通道"`。想让它们不一样，就必须在**实例创建之后**由父页面把编号传进去。

### 2.2 改法：给子控件加一个公开方法

`View/simpleView.cs` 新增：

```csharp
/// <summary>
/// 由 mainView 创建 8 张卡片时，告诉本卡片自己是第几通道。
/// </summary>
public void SetChannelNumber(int channelNo)
{
    // 设计器给的宽度是 45px，只够「通道」两个字；加上数字要加宽，
    // 否则高 DPI 或字体放大时「通道8」会被裁掉。
    uiTextBox1.Width = 55;
    uiTextBox1.Text = $"通道{channelNo}";
}
```

`View/mainView.cs` 的 `mainView_Load` 里改一行：

```csharp
for (int i = 0; i < 8; i++)
{
    var simpleView = new simpleView();
    simpleView.SetChannelNumber(i + 1);   // ← 新增：创建顺序就是通道顺序
    uiTableLayoutPanel1.Controls.Add(simpleView);
    simpleView.Show();
    simpleViews.Add(simpleView);
}
```

### 2.3 这里有三个知识点

1. **partial class**：`simpleView.cs` 和 `simpleView.Designer.cs` 是同一个类的两半。
   设计器里 `uiTextBox1` 声明成 `private`，但在 `simpleView.cs` 里照样能直接访问 —— 因为本来就是同一个类。
2. **父页面 → 子控件的通信**：不要在父页面里写 `子控件.uiTextBox1.Text = ...`（private 拿不到，也破坏封装）。
   正确姿势是**子控件暴露一个语义化的公开方法**，父页面只管调用。
3. **宽度要留余量**：设计器按 96 DPI 摆的 45px，程序运行在本机 150% 缩放、PerMonitorV2 下，
   字体物理像素会放大。「通道8」比「通道」多一个字符，提前把宽度调到 55px 最省事。

> 顺带一提：`UITableLayoutPanel` 是 4 列 2 行、按添加顺序从左到右从上到下填格子，
> 所以 `i + 1` 自然对应「通道1…通道8」，不需要手动算行列。

## 3. Bug 2：让「隐藏通道」真正能点

### 3.1 根因

`View/mainView.Designer.cs` 里 `uiButton2` 的属性设置完了就结束，少了最后那句事件绑定：

```csharp
uiButton2.Text = "隐藏通道";
uiButton2.TipsFont = new Font("宋体", 9F, FontStyle.Regular, GraphicsUnit.Point);
// ← 原来这里没有 Click +=，按钮就是个「画出来的装饰」
```

### 3.2 改法：补绑定 + 写处理函数

`View/mainView.Designer.cs` 补一行：

```csharp
uiButton2.Click += uiButton2_Click;   // 原来漏了这行，所以按钮点了没反应
```

`View/mainView.cs` 新增处理函数：

```csharp
/// <summary>
/// 「隐藏通道 / 显示通道」按钮：把上方 4×2 的通道卡片区收起 / 展开。
/// 只切 Visible，不 Dispose 卡片，也不停采集任务。
/// </summary>
private void uiButton2_Click(object sender, EventArgs e)
{
    channelsVisible = !channelsVisible;
    uiPanel2.Visible = channelsVisible;
    uiButton2.Text = channelsVisible ? "隐藏通道" : "显示通道";
}
```

再加一个字段，并在采集循环里用它跳过无用的控件刷新：

```csharp
private volatile bool channelsVisible = true;

// StartRead 的循环里：
if (!IsDisposed && IsHandleCreated && channelsVisible)
{
    for (int i = 0; i < simpleViews.Count && i < tempData.Length; i++)
        simpleViews[i].refreshData(tempData[i]);
}
```

### 3.3 四个关键概念

| 概念 | 说明 |
|---|---|
| **事件绑定** | WinForms 里「双击按钮」的本质就是设计器生成 `xxx.Click += xxx_Click;`。删掉这句，按钮还能显示、还能获得焦点，但点击不会调用任何代码。 |
| **两种绑定方式** | ① 设计器里写 `+=`（本项目风格）；② 在构造函数里 `uiButton2.Click += uiButton2_Click;`。**二选一，别两处都写**，否则点一次执行两遍函数。 |
| **Dock 布局** | `uiPanel2.Dock = Top`，`uiTitlePanel1.Dock = Fill`。把 Top 那块 `Visible = false` 后，Dock 引擎会自动让 Fill 那块吃掉空出来的高度，**不用手动改 Location/Size**。 |
| **volatile 标志位** | 采集任务在后台线程，不能在后台线程里读 `uiPanel2.Visible`（跨线程读控件属性不安全）。改成一个 `volatile bool`，后台线程读普通字段是安全的，UI 线程在按钮里写它。 |

另外顺手把状态文字同步了（原来连上串口后「当前连接：无连接」永远不变）：

```csharp
uiLight1.State = isConnected ? UILightState.On : UILightState.Off;
uiLabel3.Text = isConnected ? comName : "无连接";
```

> **设计取舍**：为什么隐藏时不直接 Dispose 卡片？因为 `mainView` 在 `Form1` 里是缓存复用的，
> 卡片销毁后要重建 8 个、还要重排表格；只切 `Visible` 成本最低，而且重新展开时下一秒数据自动回来。

## 4. Bug 3：曲线中文变方框（豆腐块）

### 4.1 根因：字体里没有汉字

ScottPlot 5 用 SkiaSharp 自己画文字，**不走 WinForms 的 GDI+ 字体回退机制**。
它的全局默认字体是 `Segoe UI`（本次实测 `ScottPlot.Fonts.Default = Segoe UI`），
这个字体不含 CJK 字形，于是每个汉字都被画成一个空方框 `□`。

所以截图里：

- 标题 `通道1 趋势（14 个点）` → `□□1 □□14 □□`
- 图例 `通道1` → `□□1`
- X 轴 `检测时间`、Y 轴 `测量值` → 一排方框

**这不是编码问题、不是数据库乱码、也不是字符串写错**，字符串本身完全正确，只是「画不出来」。

### 4.2 改法：绘图前统一指定支持中文的字体

`View/plotView.cs` 新增：

```csharp
/// <summary>
/// 修复中文变方框：ScottPlot 5 默认字体 Segoe UI 不含汉字。
/// Fonts.Detect(中文样本) 会挑系统里真正支持这套字符的字体，
/// Plot.Font.Set 会应用到标题/轴标签并改掉全局默认字体。
/// </summary>
private static void ApplyChineseFont(ScottPlot.Plot plot)
{
    string font = ScottPlot.Fonts.Detect("通道趋势测量值检测时间");
    plot.Font.Set(font);
    plot.Legend.FontName = font;   // 图例字体是独立的，单独指定一次
}
```

在 `LoadPlot()` 的 `try` 开头调用：

```csharp
try
{
    ApplyChineseFont(formsPlot1.Plot);   // ← 新增
    // ... 原来的查询、取点、Add.Scatter、Title/XLabel/YLabel/Refresh
}
```

### 4.3 这版 API 的行为（实测，别凭印象猜）

调 `plot.Font.Set("Microsoft YaHei UI")` 之后读回来的值：

```
设置前 Fonts.Default          = Segoe UI
设置后 Fonts.Default          = Microsoft YaHei UI
Title.Label.FontName          = Microsoft YaHei UI
Bottom.Label.FontName         = Microsoft YaHei UI
Left.Label.FontName           = Microsoft YaHei UI
Legend.FontName               = （空字符串，需要单独赋值）
```

两个要点：

1. `Plot.Font.Set()` **会改全局静态 `Fonts.Default`**，所以之后新建的 plottables 也自动用这个字体；
2. `Legend.FontName` 不受 `Font.Set()` 覆盖，必须单独设一次，否则图例还是方框。

`Fonts.Detect()` 比写死 `"微软雅黑"` 更稳：它按传入文字挑一个系统里**真实存在**且支持该字符集的字体
（本机返回 `Microsoft YaHei UI`），换台机器、换语言系统也不会挑到不存在的字体名。

### 4.4 为什么把 `ApplyChineseFont` 放在 `LoadPlot()` 里

`Plot.Clear()` 只清 plottables，不会重置字体，理论上构造函数里设一次就够。
但放在每次重绘前有两个好处：以后换字体只改一处；查询按钮重画、异常兜底重画都不会漏掉。

## 7. 练习题（照着改一遍才算学会）

1. **隐藏指定一路**：在工具栏加一个 `UIComboBox` 放 1~8，点按钮时只隐藏选中的那张卡片。
   提示：`simpleViews[n - 1].Visible = false`；注意 `UITableLayoutPanel` 隐藏单元格里的控件后格子还在。
2. **给卡片加合格判定**：在 `SetChannelNumber()` 之外再加 `SetLimit(double up, double down)`，
   `refreshData()` 里把 `uiTextBox3.Text` 在「合格 / 不合格」之间切换，并同步两个 `UILedBulb` 的颜色。
   提示：阈值配置已经在 `Common/yuzhiCommon.cs` 里，取 `yuzhiCommon.Current.channels[index - 1]`。
3. **字体可配置**：把 `ApplyChineseFont` 里 `Detect` 的样本字符串和字体名放到一个配置里，

## 8. 常见坑（这一轮和上一轮踩过的）

- **改 Designer.cs 要克制**：它标了「do not modify with the code editor」。补一行事件绑定没问题，
  但别把业务逻辑塞进去；VS 重新生成设计器代码时可能覆盖。更稳的做法是在构造函数里 `+=`。
- **同一事件别绑两次**：设计器绑一次、代码再绑一次 = 点一次执行两遍。
- **`Load` 可能触发多次**：`UIPage` 被反复换 `Parent` 时句柄会重建，`Load` 有可能再来一次。
  本项目已在 `mainView_Load` 加 `initialized` 幂等保护，防止重复加 8 张卡片、重复开采集任务。
- **定时器/任务不要挂 `HandleDestroyed`**：切页会重建句柄，挂在那里会让定时器永久停摆。
  要停就挂 `Disposed`。
- **后台线程不要碰控件**：更新走 `BeginInvoke` 并校验 `IsDisposed / IsHandleCreated`；
  不要在后台线程 `MessageBox.Show`；共享数组用 `Volatile` 读写。
- **命名空间分两套**：`TICP.*`（Helper/Model/Common/Properties/Program）与
  `WinFormsApp3.*`（View/Form1，绑定了 `.resx` 资源名）。只改一半就会 `CS0234`。
- **中文方框 ≠ 编码错误**：先看绘图库的默认字体，别去改数据库字段或 `Encoding.UTF8`。

## 9. 一句话总结

> Designer 决定「长什么样」，事件绑定决定「点了做不做事」，字体决定「字能不能画出来」。
> 下次再遇到界面问题，按 **界面文字 → Designer 搜控件 → 搜事件绑定 → 离屏渲染验证** 四步走，基本不会跑偏。
